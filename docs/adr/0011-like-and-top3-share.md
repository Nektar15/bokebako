# 0011 お気に入りを「いいね」に変え、結果シェアに1〜3位を載せる

- 日付：2026-10-21
- 状態：採用（Masato さんの依頼による仕様変更）

## 決めたこと

1. **開催者の「お気に入り」（SPEC 3.3・U-08）を「いいね」と呼ぶ**。押せるのは今までどおり開催者だけで、ほかの人には見せない。数は開催者画面に出すだけで、順位・並び順には使わない（順位は開催者が選ぶ）。
   - 画面：★ボタンを、ハートと「いいね」の札にした。押すと朱色になり「いいね済み」に変わる
   - URL：`POST /host/{slug}/likes/{answerId}`（旧 `/favorites/`）
   - DB の列は `answers.is_favorite` のまま（仕様書の項目名に合わせて残す。意味は「開催者のいいね」）
   - 参加者による「いいね」（SPEC 7章・13.3 で対象外）は作らない
2. **結果シェア（U-10）の投稿文と結果用 OGP 画像に、1〜3位を載せる**（SPEC は1位だけ）。
   - 投稿文：テンプレートの変数 `{ranks}`（「1位：〜」を1行ずつ）を足し、既定の文面を `{ranks}` にした。`{first}`（1位だけ）も引き続き使える
   - X の文字数の上限（280。日本語は1文字を2、URL を23と数える）に収まるよう、長い回答から順に末尾を「…」にする（余裕をみて270）
   - 画像：1〜3位を載せる（レイアウトは ADR 0012 で置き換え）
   - 非表示の回答は載せない（U-10 の表示と同じ）

## 影響

- 運用設定で結果シェアの文面を変えていた場合は、その文面が使われる（`{ranks}` を入れれば1〜3位になる）
- 結果用 OGP 画像は確定時に作る。すでに確定済みの大喜利の画像は、A-08 の「まとめて作り直す」で1〜3位版になる
