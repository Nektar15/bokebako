# 0009 画面一覧ナビ（確認用のモーダル）

- 日付：2026-10-21
- 状態：採用（確認用。本番では使わない）

## 決めたこと

1. **画面の右下に「全画面」ボタンを出し、押すと全画面へのリンクを並べたモーダルを開く**（Masato さんの依頼：全ページを確かめたい）。ユーザー向け U-01〜U-18 と管理画面 A-01〜A-10 の 38 項目。行き先は開発用データ（DevSeeder）の大喜利で、24時間たったあとの画面（募集終了・結果発表・結果未選出・非表示・削除済み）も含む。
2. **`screennav.enabled` のときだけ出す**。既定は false（本番・ステージングの Xserver では出ない）。Vercel の仮置きでは入口 `api/index.php` が既定で true にする（環境変数 `screennav_enabled=false` で消せる）。オフのときは専用のルート `/_screens/go` も作らない。
3. **本人でないと開けない画面も1回で開けるようにする**。開催者画面・開催完了は DevSeeder の開催者トークン（`dev-token-{slug}`）で開催者としてログインし、回答完了・回答一覧は DevSeeder の回答を投稿したブラウザ（`dev-browser-me`）として開く。どちらも開発用データにしか効かない。
4. **項目は `app/Config/ScreenNav.php` に置く**。画面を足したらここにも足す。モーダルは `<details>` とふつうのリンクだけで作り、JS が動かなくても開閉・移動できる（JS は背景・×・Esc で閉じるだけ）。
5. **管理画面は、ログイン後に開こうとしていた画面へ戻す**（ナビから管理画面を選ぶとログイン画面に来るため）。戻り先は管理画面の中のパスだけを受け付ける（`AdminAuthService::pullReturnUrl()`）。これは本番でも有効。

## 理由

- 最初はプルダウン（選ぶと JS で移動）にしたが、Vercel で選んでも移動しなかった。JS での送信が動かず、代わりの「移動」ボタンも JS があるときは隠していたため。ふつうのリンクなら JS の状態に左右されないので、モーダルに作り直した（2026-10-21）
- Vercel ではデプロイしてもファイルの更新日時が変わらず、CSS の `?v=` が同じままになって、1年キャッシュされた古い CSS が使われた（モーダルが崩れて見えた）。`api/index.php` で `app.assetVersion` をデプロイごとの値（`VERCEL_GIT_COMMIT_SHA` など）にした

- 開発用データは Vercel のインスタンスが起きるたびに同じ URL・同じ内容で入れ直されるので、「消えない確認用の画面」として使える。自分で作った大喜利は消える
- 本番のコードの流れ（Controller・Service）は変えず、確認用の入口を足すだけにした

## 影響

- 画面を足したら `Config\ScreenNav::$items` も更新する（`tests/Feature/ScreenNavTest` が URL の画面がすべて開くことを見る）
