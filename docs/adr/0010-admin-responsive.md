# 0010 管理画面をスマホ・タブレットに対応する

- 日付：2026-10-21
- 状態：採用

## 決めたこと

1. **管理画面をスマホ・タブレット・PC のどれでも使えるようにする**（Masato さんの判断：PC で見る人は少なく、管理者もスマホで使う。iPad の人もいる）。デザイン（`docs/design/A*.dc.html`）は PC 幅（1280px）だけなので、狭い幅の見た目はこの ADR で決める。
2. **幅の区切り**

   | 幅 | 想定 | 見た目 |
   |---|---|---|
   | 〜767px | スマホ | 左メニューは引き出し。1列。入力欄・ボタンは横いっぱい |
   | 768〜1023px | iPad 縦 | 左メニューは引き出し。2列の画面は縦に並べる |
   | 1024〜1199px | iPad 横・小さい PC | 左メニューを出す。2列の画面は縦に並べる |
   | 1200px〜 | PC | デザインのとおり |

3. **左メニューは、上のバーの「メニュー」で開く引き出しにする**（1024px 未満）。チェックボックスと `<label>` で開け閉めするので JS がなくても動く。JS があればキーボード（Enter・Space・Esc）でも動く（`components/admin-menu.js`）。「メニュー」の横に未処理の件数（通報＋お問い合わせ）を出す。
4. **表は、狭いときに行をカードにする**。画面の幅ではなく、表が入っている枠の幅で切り替える（CSS のコンテナクエリ。`c-panel--table`）。各値の前に列名を小さく出す（セルの `data-label`）。列の多い大喜利・回答の一覧は、広めの幅（1000px）からカードにする。
5. **タッチの端末では押しやすくする**：ボタンは高さ 38〜44px、入力欄は 44px。入力欄の文字は 16px にする（iPhone・iPad で入力欄を押したときに画面が拡大されないように）。
6. **一覧と詳細が並ぶ画面（A-05 通報・A-09 お問い合わせ）**は、狭いときは一覧の下に詳細を出す。一覧のカードを押すと詳細の位置まで進む（`#detail`）。
7. **A-10 運用設定**は、狭いときは「設定を保存する」を画面の下に貼りつける。

## 理由

- 管理者が使う端末に合わせる。表の横スクロールは、スマホでは見落としや押し間違いが多いのでやめ、カードにした
- 画面ごとの HTML は変えず（セルに列名を足しただけ）、CSS で切り替えたので、PC の見た目と動き（Controller・Service）は変わらない

## 影響

- 管理画面を変えたら、スマホ幅（390px）・iPad 縦（820px）・iPad 横（1180px）・PC（1440px）で横にはみ出さないことを見る（CODING_RULES のチェックリスト）
- 表に列を足したら、セルに `data-label`（列名）をつける。操作ボタンのセルにはつけない
- コンテナクエリは iOS 16（Safari 16）以降で動く。それより古い端末では、表が横にはみ出す
