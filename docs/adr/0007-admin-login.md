# 0007 A-01 管理者ログインと管理者アカウント（二段階認証の前まで）

- 日付：2026-10-20
- 状態：採用（数値と 4 は【仮】。発注者の確認待ち）

二段階認証（TOTP）は最終工程に回す（発注者の指示）。今回は ID・パスワードの認証、試行回数制限、セッション、ログアウト、IP 制限、管理者アカウントの管理までを作り、仮認証（CODING_RULES 7-1）を削除した。

## 決めたこと

1. **認証はセッション**（CodeIgniter の Session。Cookie `bk_session`）。ログイン成功でセッション ID を作り直す。セッションには管理者 ID・パスワードハッシュから作った印・ログイン時刻・最終操作時刻を持ち、毎リクエスト `admins` を読み直す。権限の変更・削除・パスワード変更はほかの端末にもすぐ効く。
2. **【仮】数値**（`AdminAuthService` の定数）：同じアカウントで5回続けて失敗したら15分ロック。同じ IP からは10分で20回まで（存在しない ID も数える）。無操作120分、ログインから最長12時間でログインし直し。パスワードは12文字以上・ID を含めない（`AdminAccountService::PASSWORD_MIN`）。
3. **ID の有無を言い分けない**。ID 違いとパスワード違いは同じ文言。存在しない ID でもダミーのハッシュで `password_verify()` を1回通し、応答時間をそろえる。ロック中だけは「一時的に停止」と出す（本人が気づけるように）。
4. **【仮】管理者アカウントの画面（未確定事項10）**：`/{admin}/accounts`、画面 ID は A-01 の一部として「A-01 管理者アカウント」。左メニューの最後に置く。上位管理者は一覧・追加・名前と権限の変更・パスワード再設定・削除ができる。一般管理者は自分のパスワード変更だけ。自分の権限変更・自分の削除・上位管理者を0人にする操作はできない。最初の上位管理者は `php spark admin:create` で作る。
5. **IP 制限（SPEC 3.4「任意」）は `ADMIN_ALLOWED_IPS`**。どの環境でも、値があれば管理画面（ログイン画面を含む）をその IP だけに絞る。空なら制限しない。以前の「staging の仮管理者用」という意味はなくした。
6. **二段階認証を足す場所**：`LoginController::login()` で `verifyPassword()` が通ったあと、`startSession()` の前に TOTP の確認画面を挟む。`admins.totp_secret` は作ってあり、まだ使っていない。
7. **「ID またはメールアドレス」（SPEC A-01）は `login_id` 1列で受ける**。ID にメールアドレスを使ってよい（英数字と `. _ @ + -`）。メールアドレス用の列は足さない。
8. **ログイン後の画面は `Cache-Control: no-store`**。ログアウト後にブラウザの「戻る」で管理画面が見えないように。
9. **開発用の管理者は DevSeeder に入れる**（`dev-admin` 上位、`dev-general` 一般。パスワードは `DevSeeder::ADMIN_PASSWORD` で公開されている）。本番で DevSeeder を流さないことは README のリリース前チェックにある。

## 理由

- 1：仮認証のときから Controller・Service は `CurrentAdminService` から管理者を受け取っている。Filter の中身を替えるだけで済む（CODING_RULES 7-1）。
- 2：SPEC は「一定回数失敗で一時ロック」「セッション管理（有効期限）」とだけある。よく使われる値にした。
- 4：SPEC A-01 の機能にあるが画面定義がない。新しい画面 ID を作らず A-01 の中に置いた。

## 影響

- 管理画面のテストは `DatabaseTestCase::asAdmin()` でログイン済みにする。`?role=general` はなくなった
- 本番に出す前に、`cookie.secure = true` を `.env` に入れる（README の表）
- 二段階認証を入れるまでは、パスワードだけで管理画面に入れる。本番に出すかどうかは発注者と決める（HANDOFF）
