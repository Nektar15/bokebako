# 0006 工程5後のコードレビュー（2026-10-20）で直したこと

- 日付：2026-10-20
- 状態：採用（3 の上限値と 5 は【仮】）

外部のコードレビュー（P1 5件・P2 2件）を受けて直した。指摘の番号はレビュー文書のもの。

## 決めたこと

1. **結果の確定は「選んだ回答がすべてこの大喜利の公開中の回答」でなければ全体を拒否する**（指摘 1）。開催者の確定（U-09）と管理者の代理変更（A-03）は `HostService::saveRanks()` を共通で通る。以前は合わない回答を黙って飛ばし、0件でも `decided` にしていた。非表示の回答を飛ばして残りを2位にする挙動もやめた（テストの期待値も変更）。
2. **結果ページ（U-10・U-12）には「あなたの回答」を付けない**（指摘 2）。全員で共有するページキャッシュに載るため。印は U-07（回答一覧。キャッシュしない）だけに付ける。FEATURES.md でも `isMine` は U-07 の項目にだけある。
3. **レート制限は「操作＋ブラウザID＋IP」に加えて「操作＋IP」でも数える**（指摘 3）。ブラウザIDは Cookie なので利用者が変えられる。【仮】IP 単位の上限はブラウザ単位の 5 倍（`RateLimitService::IP_FACTOR`）。携帯回線・学校などで IP を共有する人を巻き込みにくくするため。合言葉はブラウザIDで数えず、「IP＋大喜利」5回・「IP」20回・「大喜利」30回／10分（`PASSPHRASE_*`）。
4. **状態の変更は「読んだときの状態のまま」を条件にした更新にする**（指摘 4）。確定（`HostService::markDecided()`）、S-01・S-02（`LifecycleService::transition()`）。条件に合わなければ何もしない（確定は ALREADY_DECIDED、cron は飛ばす）。行ロック（`SELECT … FOR UPDATE`）は SQLite のテスト DB で使えないので採らない。条件付き UPDATE は MariaDB でも行ロックを取るので、同時に来ても後の方は 0 件になる。
5. **締切後に再公開した募集中の大喜利は、結果選択待ち＋S-01 と同じ選出期限にする**（指摘 6）。【仮】選出期限もすでに過ぎていれば、その場で結果未選出にはせず、次の S-02（1分以内）に任せる。遷移と OGP 生成・操作履歴を S-02 の1か所にまとめるため。
6. **ページキャッシュのキーに `page` クエリだけを含め（`Config\Cache::$cacheQueryString = ['page']`）、`?page=` 付きは保存しない**（指摘 5）。クエリなしのキーは以前と同じなので、`PageCacheService::purgeOogiri()` はそのまま。
7. **非表示・削除で OGP 画像を消し、再公開で作り直す**（指摘 7）。大喜利は募集・結果・その回答のシェア用の画像を消す。回答はシェア用を消し、結果画像を今の公開状態で作り直す（1位は「順位のある公開中の回答の最上位」で、U-10 の表示と同じ）。生成に失敗したら古い画像は消す（既定の画像が出る）。

## 理由

- 1・4：確定済みなのに選出 0件、あるいは後から来た確定が先の結果を上書きすると、結果ページと X に出た結果が食い違い、開催者が直せない。
- 2・6：SPEC 4.1 のページキャッシュは残したい（100万PV対応）。キャッシュを止めずに、キャッシュに載せる内容とキーの方を直した。
- 3：CODING_RULES 7章のキー（ブラウザID＋IP）は残し、IP 単独の枠を足した。キーを変えるのではなく足すので、7章の文言とは矛盾しない。
- 7：非表示にした本文が `public/ogp/` に残り、URL を知っていれば見られた。

## 影響

- `HostService::saveRanks()` の引数に「確定してよい今の状態」が増え、1位の回答を返す
- `AnswerService::listVisible()` の第3引数（本人の印を付けるか）が必須になった
- 管理者は、非表示・削除中の大喜利のベスト回答を変更できない（再公開してから変える）
- CDN（README の Cloudflare）を使う場合、消した OGP 画像は CDN のキャッシュが切れるまで配信される。すでに SNS 側に取り込まれた画像は消せない（docs/admin-manual.md）
- テストの土台 `tests/_support/DatabaseTestCase.php`：ページキャッシュがテスト用のキャッシュではなく `writable/cache/` のファイルに書かれ、テストや実行をまたいで古い HTML が返っていたのを直した
