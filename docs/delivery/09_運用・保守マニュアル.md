# 09 運用・保守マニュアル

詳しい手順の原本は `README.md`（Xserver・cron・`.env`・リリース前チェック）、`docs/vercel.md`（仮置き）、`docs/admin-manual.md`（管理画面の操作）。ここでは、手順の流れと、この作業で変わったところをまとめる。

## 1. 環境構築（ローカル）

```sh
cp .env.example .env          # DB を設定（SQLite でも可：database.default.DBDriver = SQLite3、database = パス）
composer install
php spark migrate --all -n App
php spark db:seed DevSeeder   # 開発用データ（全テーブルを消して入れ直す）
php spark serve
composer check                # 整形・静的解析・テスト
cd tests/e2e && npm install && npm test   # E2E（tests/e2e/README.md）
```

PHP は 8.2（8.5 では PHPStan 1.12 が止まる。HANDOFF「開発環境のメモ」）。

## 2. デプロイ（本番：Xserver）

1. `develop` を確認：`composer check` と E2E が通っている
2. サーバーでリポジトリを更新（`git pull`。`public/` を変えたら `public_html/` にもコピー）
3. `.env` の `app.assetVersion` を変える（例：日付）
4. `php spark migrate`（この作業ではマイグレーションの追加なし）
5. ページキャッシュを捨てる：`writable/cache/` の中身（`index.html` 以外）を消す（キャッシュ配信のページに新しい計測を入れるため。消さなくても TTL で入れ替わる）
6. README「リリース前チェック」の 5・6 を確かめる

## 3. デプロイ（仮置き：Vercel）

`develop` に push すると Production に入る（`docs/vercel.md`）。**外部 DB につなぐ手順は `docs/vercel.md` 2-2**（ADR 0015。つながないと同時アクセスの多くが 404）。

## 4. 環境変数

README「本番の `.env` で必ず設定するもの」のとおり。この作業で足したもの：

| キー | 内容 |
|---|---|
| `database.default.sslCA` | TLS が必須の外部 DB の CA 証明書のパス（Vercel の仮置きだけ。本番は空） |

運用設定（管理画面 A-10）に「回答シェア（ほかの人の回答）」を足した（既定「このボケ好き：{answer}」）。

### SEO

- `/robots.txt` と `/sitemap.xml` はアプリが返す（`public/robots.txt` は置かない。置くとそちらが優先される）
- サイトマップを検索エンジンに登録するときは、Google Search Console に `https://<ドメイン>/sitemap.xml` を送る

## 5. マイグレーションと戻し方

- 進める：`php spark migrate`
- 戻す：`php spark migrate:rollback`（直前のまとまりを戻す）
- この作業ではスキーマを変えていない。合言葉のハッシュの形式（`v2$`）は、コードを前の版に戻すと照合できなくなる（6 章のロールバックの注意）

## 6. ロールバック

1. 前のコミットに戻す：`git checkout <前のタグかコミット>`（または前のリリースのフォルダに切り替える）
2. `app.assetVersion` を変え、ページキャッシュを捨てる
3. **注意**：この作業のあとに作った大喜利の合言葉は新しい形式（`v2$`）で、前の版では照合できない（開催者 Cookie は使える）。合言葉で入れないという問い合わせが来たら、その大喜利の開催者ページは Cookie のある端末から開いてもらう
4. Vercel：Deployments で前のデプロイを「Promote to Production」

## 7. バックアップと復旧

- バックアップ：README「バックアップ」（DB は Xserver の 14 日＋`mysqldump` の日次）
- 復旧：`mysql < dump.sql` で戻す → `writable/cache/` を消す → OGP 画像は A-08「公開中の画像をまとめて作り直す」で作り直せる

## 8. ログ

| 何 | どこ |
|---|---|
| アプリのエラー | `writable/logs/log-YYYY-MM-DD.log` |
| cron | `writable/logs/cron.log` |
| 管理者・開催者の操作 | 管理画面の各画面の履歴（`admin_logs`） |
| Vercel | Vercel の Logs。準備の失敗は `/tmp/bokebako/logs/vercel-setup.log`（外からは見えない） |

## 9. 障害のときの対応

| 症状 | まず見る所 | 対応 |
|---|---|---|
| 画面が 500 | `writable/logs` | 直前のデプロイなら 6 章で戻す |
| 締め切られない・結果が出ない | `cron.log`、cron の登録 | `php spark cron:minute` を手で流す |
| X のカードが出ない | 大喜利の URL の `og:image` を開いて 200 か | A-08 で画像を作り直す。フォント（`ogp.font`）を確認 |
| 合言葉で開けないという問い合わせ | 試行の上限（10 分）に当たっていないか | 時間をおいてもらう。6 章の注意も確認 |
| Vercel で作った大喜利が 404 | DB の設定が SQLite のままでないか | `docs/vercel.md` 2-2 |
| Vercel で開発用データの一部が欠けている | デプロイ直後の同時の準備（2026-10-24 以前の版で起きた） | TiDB で `DROP DATABASE bokebako; CREATE DATABASE bokebako;` → Redeploy |
| 通報が急に増えた | A-05 | 一時非表示。通知メールのまとめ（`surge_count`） |
