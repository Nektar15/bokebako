## 1. システム概要

「ぼけばこ」は、登録なし・匿名で遊ぶ 24 時間限定の大喜利サービス。お題を出した人（開催者）が X で回答を募り、集まったボケから開催者がベスト 3 を選んで発表する。

## 2. 構成

| 層 | 内容 |
|---|---|
| サーバー | PHP 8.2、CodeIgniter 4.6（`system/` に同梱） |
| 画面 | サーバーで HTML を作る。CSS・JS は素のファイル（ビルドなし）。JS なしでも開催・回答・発表・問い合わせ・管理者ログインが通る |
| DB | 本番 MariaDB 10.5（Xserver）。テスト SQLite。Vercel の仮置きは外部の MySQL 互換 DB を推奨（ADR 0015） |
| 自動処理 | cron 1 分ごとに S-01（締め切り）・S-02（結果の期限）・S-04（通報）・S-05（AI 判定）、日次 S-06（集計）、S-07（OGP の取りこぼし） |
| 外部 | X（投稿画面を開くだけ）、GA4、Cloudflare Turnstile、OpenAI、メール |

## 4. 主な流れ

1. **開催**：お題と合言葉（必須）を入れ、確認して開催。開催者トークンを Cookie と localStorage に置く
2. **募集**：U-03 から X の投稿画面、または OS の共有シート。開催者が自分の募集 URL を開いても募集のシェアが出る
3. **回答**：募集 URL を開いた人が回答。回答すると「みんなのボケ」を見られる
4. **発表**：24 時間後に締め切り。開催者が 72 時間以内に 1〜3 件を選んで確定
5. **別の端末**：`/host/{slug}` で合言葉を入れると開催者ページが開く

## 5. 業務ルール（変更したもの）

| ルール | 内容 | 根拠 |
|---|---|---|
| 合言葉 | **必須**、4〜32 文字。前後の空白（全角を含む）と見えない文字を取り、NFKC でそろえてから照合。保存は SHA-256 → bcrypt（以前の形式も照合できる） | ADR 0015-3 |
| 回答のシェア文 | 自分の回答は `tpl_answer`（「俺の回答」）、ほかの人の回答は `tpl_answer_other`（「このボケ好き」） | ADR 0015-7 |
| 並び順 | U-07 は新着順（既定）・古い順。同じ日時は ID 順 | ADR 0015-4 |
| 開催の一覧 | このブラウザで開催したもの（トークンが今も正しいもの）だけ。ほかの人には見えない | ADR 0015-2 |
| 締め切り後の回答 | 登録せず、理由を添えた U-11 を 409 で返す | 監査 N-09 |

そのほかのルール（文字数、NG ワード、連続投稿の制限、通報、AI 判定、状態遷移）は `docs/FEATURES.md` と ADR 0003〜0007 のとおり。

## 6. 入力とエラー

| 項目 | 規則 | エラー文 |
|---|---|---|
| お題 | 1〜`odai_max`（既定 100）文字。制御文字・NG ワード（拒否）不可 | 「お題を入力してください」「お題は100文字以内で入力してください」ほか |
| 合言葉 | 4〜32 文字（整えたあと） | 「合言葉を入力してください」「合言葉は4〜32文字で入力してください」 |
| 回答 | 1〜`answer_max`（既定 140）文字。制御文字・NG ワード（拒否）不可 | 「ボケを入力してください」「回答は140文字以内で入力してください」ほか |
| 本人確認 | 試行は IP＋大喜利 5 回・IP 20 回・大喜利 30 回／10 分 | 「合言葉が違います」「試行回数の上限に達しました…」 |

## 7. API（`/api/v1`、JSON。POST は `Content-Type: application/json` か `X-Requested-With`）

| メソッド・パス | 内容 |
|---|---|
| `GET o/{slug}/status` | 残り時間・回答数・状態 |
| `POST events` | 自前の計測（pv・シェア・新規開催クリック） |
| `POST reports` | 通報 |
| `GET ads` | 広告枠 |
| `GET ogp/{kind}/{key}` | OGP 画像の中身（Vercel の画像生成用） |
| `POST hosted` **（新規）** | `{items:[{slug, token}]}` → このブラウザで開催した大喜利。正しいトークンのものだけ。最大 20 件、同じ IP から 1 分に 30 回まで |

レスポンスの形は `{ok: true, data}`／`{ok: false, error: {code, message}}`（CODING_RULES 11 章）。

テーブルは 14（`docs/db.md`）。この作業で**スキーマの変更はない**。

## 9. 認証・認可

| 対象 | 方法 |
|---|---|
| 開催者 | Cookie `bk_host_{slug}` の開催者トークン（DB はハッシュ）。なければ localStorage の控えで復元、または合言葉 |
| 回答者 | 匿名ブラウザ ID（Cookie `bk_bid`）とサーバーの投稿記録 |
| 管理者 | ID・パスワード（ADR 0007）。IP 制限（任意）。**二段階認証は未実装（最終工程）** |
