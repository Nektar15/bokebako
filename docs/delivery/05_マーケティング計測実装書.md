# 05 マーケティング計測実装書

## 1. 目的と KPI

X からの自然な拡散で、開催と回答を増やす。

| KPI | 見る所 |
|---|---|
| 開催数・開催の完了率（開始 → 完了） | GA4：`event_create_start` → `event_create_complete`。管理画面 A-02 |
| 回答数・回答の完了率（閲覧 → 開始 → 完了） | GA4：`event_page_view` → `answer_start` → `answer_complete` |
| シェアのクリック率・共有の完了 | GA4：`share_x_click`、`share_complete` |
| 派生開催（見た人が自分も開催する） | 自前の events：`click_create`、A-02 の派生開催係数 |

## 2. ファネル

SNS 流入（`page_view`、参照元 x.com／t.co）→ 開催ページの閲覧（`event_page_view`／`answer_page_view`）→ 回答の開始（`answer_start`）→ 回答の完了（`answer_complete`）→ シェアのクリック（`share_x_click`）→ 再流入（シェアした URL からの `page_view`。`answer_page_view` は回答のシェア URL からの流入）

## 3. 構成

- GA4（gtag.js）。測定 ID は `.env` の `app.ga4Id`。**未設定なら何も送らない**（タグも読まない）
- GTM は使わない（既存の構成。CSP の許可先も gtag だけ）
- 自前の計測（`/api/v1/events` → `events` テーブル → S-06 の日次集計 → A-02）は今までどおり。名前も変えていない（ADR 0015-6）
- 実装：`public/assets/js/components/tracking.js`（`ga()`）、`app/Views/partials/ga_event.php`（表示時のイベント）、`public/assets/js/components/web-share.js`、`doc-sheet.js`

## 4. イベント

| イベント | 発火の条件 | パラメータ | 実装箇所 |
|---|---|---|---|
| `page_view` | 全ページ（GA4 の自動） | GA4 の標準 | `tracking.js`（`gtag('config')`） |
| `event_create_start` | U-01 のお題の欄に最初に入力したとき（1 ページで 1 回） | — | `u01_top.php`（`data-js-ga-start`） |
| `event_create_complete` | U-03 を表示したとき。同じタブで同じ大喜利は 1 回だけ | `oogiri` | `u03_created.php` |
| `event_create_error` | 開催の入力エラーで U-01 に戻ったとき | `fields`（エラーの項目名。例 `passphrase`） | `u01_top.php` |
| `answer_start` | U-04 の回答の欄に最初に入力したとき | `oogiri` | `u04_answer.php` |
| `answer_complete` | U-06 を表示したとき。同じタブで同じ回答は 1 回だけ | `oogiri` | `u06_answered.php` |
| `answer_error` | 回答の入力エラーで U-04 に戻ったとき／締め切り後に送ったとき | `oogiri`、`fields`（締め切りは `closed`） | `u04_answer.php`、`u11_closed.php` |
| `share_x_click` | X のシェアボタンを押したとき | `share_type`（recruit／answer／result）、`oogiri` | `tracking.js`（`data-js-track` の share_*） |
| `share_complete` | **OS の共有シートで送り終えたときだけ**（Web Share API の完了） | `method`（web_share）、`share_type`、`oogiri` | `web-share.js` |
| `event_page_view` | 大喜利のページ（U-04・U-10・U-11・U-12）を表示したとき | `oogiri`、`status` | 各 View |
| `answer_page_view` | 回答のシェア URL を開いたとき | `oogiri`、`answer_id` | `u04_answer.php`、`answer_share_closed.php` |
| `organizer_page_view` | 開催者ページ（U-08）を表示したとき | `oogiri` | `u08_host.php` |
| `sort_change` | みんなのボケの並び順を押したとき | `sort`（new／old）、`oogiri` | `u07_list.php`（`data-js-ga`） |
| `guideline_view` | 規約・ガイドラインのページを表示したとき／U-02 のシートで開いたとき | `doc`（terms／guidelines）、`via`（page／modal） | `u15_terms.php`、`u17_guidelines.php`、`doc-sheet.js` |
| `click_create` | 「自分も大喜利を開催する」を押したとき（自前の計測と同じ名前で GA4 にも） | `oogiri` | `tracking.js` |

### X の投稿と完了の違い

X のボタンは X の投稿画面を開くだけで、実際に投稿したかは分からない。そのため `share_x_click`（押した）だけを送り、`share_complete` は送らない。`share_complete` は共有シートの完了（`navigator.share()` が成功で終わった）だけ。

## 5. 二重計測の防止

- 完了イベント（`event_create_complete`・`answer_complete`）は sessionStorage の印 `bk:ga:{イベント}:{対象}` で、同じタブでは 1 回だけ（再読み込み・戻るで増えない）
- 入力の開始は、1 ページで最初の入力の 1 回だけ
- 自前の計測は今までどおり（シェアは同じブラウザ・IP・大喜利で 1 時間に 1 回、IP ごとに 1 分 120 件まで）

## 6. プライバシー

- 合言葉・お題や回答の本文・IP・ブラウザ ID は GA4 に送らない（E2E で確かめている）。送るのはスラッグ（公開 URL の一部）と回答 ID、画面の状態だけ
- 同意の管理（Cookie バナー）は今の仕様にない。プライバシーポリシー（U-16）に GA4 の利用を書くこと、同意の取り方は発注者の判断（外部設定の残り）

## 7. 検証

| 項目 | 結果 |
|---|---|
| イベントの名前・パラメータ・二重防止・秘密を含まないこと | PASS（E2E `tracking.spec.mjs`。gtag を差し替えて送った内容を確認。2026-10-22） |
| GA4 に実際に届くこと（DebugView） | **BLOCKED**（測定 ID がない）。実装済み・未検証 |

DebugView での確かめ方：`.env` に `app.ga4Id = G-XXXX` を入れる → Chrome の拡張「Google Analytics Debugger」を有効にする → 上の表のとおり操作 → GA4 の管理 → DebugView で名前とパラメータを見る。

## 8. ダッシュボード（GA4 で作るもの）

1. 探索 → ファネル：`page_view`（x.com 参照）→ `event_page_view` → `answer_start` → `answer_complete` → `share_x_click`
2. 探索 → ファネル：`event_create_start` → `event_create_complete` → `share_x_click`（share_type=recruit）
3. カスタムディメンション：`share_type`、`status`、`sort`、`fields`、`doc`、`via`（イベントスコープ）

## 9. 外部の設定の残り

- GA4 のプロパティと測定 ID（`app.ga4Id`）
- カスタムディメンションの登録（上の 8-3）
- プライバシーポリシーへの記載と、同意の取り方の判断
