## 2. 最重要：Vercel では DB がインスタンスごとに別（N-01、P0／仮置き環境）

Vercel の PHP 関数は、同時アクセスが増えると複数のインスタンスで動く。各インスタンスが自分の `/tmp` に SQLite を持つため、**作った大喜利・回答・開催者情報が、ほかのインスタンスからは見えない**。インスタンスは数分で入れ替わり、そのたびにデータが初期状態に戻る。

再現（2026-10-22）：
1. Vercel で大喜利を作成（`/o/MYhjXL3e`）。直後に順に 15 回開くと全部 200
2. 同じ URL へ**同時に 40 件**送ると、**200 が 11 件・404 が 29 件**
3. 約 10 分後には、開催者 Cookie を付けても `/o/MYhjXL3e/created` が 30 件すべて 404（データが消えた）

この環境で触ると、下の既知の不具合の多くが「起きる」。

| 既知の不具合 | Vercel で起きるしくみ |
|---|---|
| BUG-001 X のカードが出ない | X のクローラーは別のインスタンスに来る → 大喜利が見つからず 404。OGP 画像（`api/og.js`）も PHP の API から中身を取るので、同じ理由で既定の画像か 404 |
| BUG-004 回答リンクが開けない | 回答の URL を開いた人は別のインスタンスに来る → 302 で募集 URL へ → そこも 404 |
| BUG-005 開催者ページが開けない | `/host/{slug}` が別のインスタンスに来ると 404。データが消えたあとも 404 |
| BUG-003 スマホで「Xで回答を募集する」が出ない | このボタンがあるのは U-03（開催完了）だけ。U-03 を開けなかったり（404）、開催者だと分からなかったりすると、ボタンのない U-04 へ回される（下の 3-3） |

直すには、Vercel でも**全インスタンスで共有する外部 DB** を使うしかない（コードの修正では直らない）。ADR 0008 で「外部 DB を用意しない」と決めているので、**方針を変える判断が要る**（DECISIONS.md D-01）。

## 3. 既知の不具合の原因

### BUG-001：X 用の OGP（分類 C、P1）

- 大喜利のページ（`/o/{slug}`）・回答のページ（`/o/{slug}/a/{id}`）の HTML には、JS を動かす前から `og:title`・`og:description`・`og:image`・`og:url`・`twitter:card=summary_large_image` がある（Twitterbot の UA で取得して確認）。OGP 画像は 1200×630 の PNG、HTTPS、200、`image/png`、`robots.txt` で拒否していない
- **主因は N-01**（クローラーが 404 を受け取る）
- そのほかの問題：
  - **トップ（`/`）に OGP がない**（N-05、P2）。トップの URL をシェアしてもカードが出ない
  - 回答のページの `og:description` が募集の文言のままで、回答の中身が入っていない（N-06、P3）
  - `og:site_name`・`og:type`・`og:image:width/height`・`og:image:alt` がない（P3。なくてもカードは出るが、付けたほうが確実）
- **X 上での実表示は未確認**。X の Card Validator は廃止されているので、本番相当の環境に投稿して目で確認する手動の項目になる

### BUG-002：合言葉を入れると開催できない（分類 C、P1）

- **原因 1（再現した）**：合言葉が 4 文字未満だとサーバーの検証で落ちる。ところが U-01 の画面に**合言葉のエラーを出す場所がない**（`app/Views/front/u01_top.php` はお題と `_` のエラーしか出さない）。結果として、ボタンを押しても何も起きずにトップへ戻るように見える。Playwright で `abc` を入れると、エラー表示 0 件のままトップに戻った
- **原因 2（再現した）**：開催時は `Text::clean()`（全角スペースや見えない文字も取る）で整えてから保存するのに、本人確認では `trim()`（半角しか取らない）で照合する（`HostService::recover()`）。前後に全角スペースがある合言葉は、**同じものを入れても「合言葉が違います」**になる
- 原因 3（コードから確認）：最大の長さがない。`password_hash()`（bcrypt）は 72 バイトまでしか見ないので、日本語は先頭の約 24 文字だけで照合される（P3）
- 注：このサービスの合言葉は「開催者が別の端末で開催者ページを開くため」のもので、回答の投稿には使わない（SPEC U-01・U-08）。「回答に合言葉が要る」という意味の要望であれば仕様の変更になる（DECISIONS.md D-03）
- 合言葉は URL・ログ・計測イベントには出ていない（Cookie・POST の本文だけ。DB はハッシュ）

### BUG-003：スマホで「Xで回答を募集する」が出ない（分類 E→C、P1）

- iPhone 13・Pixel 7 の画面サイズで U-03 を開くと、ボタンは表示された（幅 350px、`display:none`・メディアクエリ・z-index・overflow の問題なし）
- このボタンがあるのは **U-03（開催完了）だけ**。U-08（開催者ページ）は「Xで再募集する」、U-04（回答画面）にはない
- 考えられる原因（実機で絞り込みが要る）：
  1. **N-01**：開催直後の `/o/{slug}/created` が別のインスタンスで 404、または開催者 Cookie が効かずに U-04 へ回される
  2. スマホで、別の端末・X アプリ内のブラウザで開いている → Cookie がないので U-03 は U-04 へ回される（今の仕様どおりの動き）
- 指示どおり、**Web Share API（スマホの共有シート）と X の投稿 URL を使い分ける**作りにする（第 5 章）

### BUG-004：回答リンクが開けない（分類 C、P1）

- ローカルでは、作った直後・別のブラウザ・再読み込みのどれも 200 で開けた。Vercel では N-01 で 404
- 存在しない回答・非表示の回答・非表示の大喜利の回答は、**404 ではなく募集 URL へ 302**（N-08、P3）。指示（「存在しない回答は 404」）と違う。非公開の中身は出ていない

### BUG-005：開催者ページが開けない（分類 C＋E、P1）

- `/host/{slug}` は、開催者のブラウザなら U-08、それ以外では合言葉の入力（「開催者の確認」）を出す。ローカルでは期待どおりに動いた。Vercel では N-01 で 404
- **「公開プロフィールと開催履歴を表示する」は今の仕様と食い違う**。SPEC 1.4・11章で「ユーザープロフィール」は対象外。今のページは開催者だけが開く非公開のページで、開催者を識別する ID（アカウント）もない（DECISIONS.md D-02）

### BUG-006：開催の合言葉を必須にする（分類 D、P2）

- 今は任意（ADR 0004-8【仮】）。必須にするのは発注者の判断として受け取る
- 既存の大喜利（合言葉なし）はそのまま開催者 Cookie で使えるようにし、DB の変更は不要（`passphrase_hash` は null のまま残す）
- 決めること：最小・最大の文字数、全角と半角をそろえるか（DECISIONS.md D-03）

### BUG-007：開催モーダル内の利用規約・ガイドライン（分類 B、P2）

- U-02 のモーダルにある「利用規約」「投稿ガイドライン」は、**同じタブで別のページへ移る**。Chromium では「戻る」でお題が残ったが、モーダルは閉じてしまい、Safari（ページのキャッシュが効かない場合）では入力が消えるおそれがある（実機は未確認）

### BUG-008：「みんなのボケ」のシェア文がすべて「俺の回答」になる（分類 C、P2）

- 回答のシェア文のひな形は `tpl_answer`（`お題：{odai}\n俺の回答：{answer}\n{url}`）の 1 種類だけ。U-06（自分の回答）でも、U-07・U-10・U-12（ほかの人の回答）でも同じものを使う（`ShareService::answerIntent()`）
- 再現：U-07 で、ほかの人の回答のシェア文も「俺の回答：別の人のボケ」になった
- URL は回答ごとに正しい（`/o/{slug}/a/{id}`）

### BUG-009：「みんなのボケ」に並び替えがない（分類 D、P2）

- U-07 は新着順だけ（SPEC U-07「回答一覧（新着順）」どおり）。並び替えの UI はない
- **「人気順」の元になるデータがない**。いいねは開催者だけが付けられ（ADR 0011）、閲覧者の反応は記録していない（DECISIONS.md D-04）
