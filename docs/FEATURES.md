# ぼけばこ 機能一覧

開発仕様書 Ver.1.0（開発仕様書_坂井.docx）の第5〜9章をもとに、画面ごと・システム全体で必要な機能を洗い出したものです。実装はこの一覧と `CODING_RULES.md` に従って進めます。

## 凡例

- 【外】…外側で実装するもの。View、CSS、JS、ルーティング、ダミーデータでの表示。先行して実装する。
- 【内】…中身で実装するもの。Service、Model、DB、cron、外部API。外側の完成後に実装する。
- 優先度は仕様書のとおり（A：必須／B：事業上重要／C：予算内で実装）。
- 「設定値」と書いた数値は固定値にせず、運用設定（A-10）から読み込む。

## 0. システム全体の共通機能

### 0-1. 共通レイアウト・表示

- 【外】共通レイアウト：ヘッダー（ロゴ、遊び方リンク）、フッター（規約類4リンク、コピーライト）
- 【外】広告枠パーツ：上部・下部の2種類。広告がないときは枠ごと非表示
- 【外】metaタグの出し分け：title、description、canonical、OGP（og:title／og:description／og:image／og:url）、Twitter Card（summary_large_image）
- 【外】GA4タグの読み込み（測定IDは `.env` から取得。未設定なら出力しない）
- 【外】確認モーダルの共通部品（U-02・U-05・U-09、削除確認で使う）
- 【外】通報モーダルの共通部品（理由の選択式、送信完了表示）
- 【外】トースト表示の共通部品（「コピーしました」「通報を受け付けました」など）
- 【外】エラーページ：404、500、アクセス制限（429）、メンテナンス
- 【外】日時表示の共通フォーマット（例：「9月17日 22:15」）と、残り時間表示（例：「残り 18時間32分」）
- 【内】日時はすべて Asia/Tokyo で扱う

### 0-2. 識別・認証

- 【内】匿名ブラウザIDの発行：初回アクセス時にCookieへ保存。有効期限は長期で、値は推測困難なランダム値
- 【内】投稿元識別情報の保存：IPとブラウザIDはハッシュ化して保存。生IPは一定期間後に削除（期間は未確定）
- 【内】開催者トークン：開催時に発行し、DBにはハッシュのみ保存。ブラウザにはCookie／localStorageで保持
- 【内】合言葉による開催者の本人確認：照合の試行回数を制限する
- 【内】管理者認証：パスワード＋二段階認証（TOTP）、ログイン試行制限、セッション期限（A-01）

### 0-3. 入力チェック・不正対策

- 【外】クライアント側の文字数カウントと上限表示（あくまで補助）
- 【内】サーバー側の入力チェック：必須、文字数（設定値）、制御文字・禁止文字の除去または拒否
- 【内】NGワード判定：完全一致／部分一致／正規表現。「投稿拒否」なら即エラー、「要確認」なら投稿を通したうえで管理画面に記録
- 【内】レート制限：開催・回答・通報のそれぞれにかける。閾値（回数・時間窓）と制限方法は設定値
- 【外】CAPTCHAの表示枠（レート制限時、お問い合わせ時）
- 【内】CAPTCHAの検証（サービスは未確定）
- 【内】CSRF対策：すべてのPOSTに適用
- 【内】セキュリティヘッダーの付与、HTTPからHTTPSへのリダイレクト

### 0-4. 状態管理と振り分け

- 【内】大喜利の状態遷移：`open`（募集中）→ `awaiting_selection`（結果選択待ち）→ `decided`（結果確定）または `no_result`（結果未選出）。別系統として `hidden`（一時非表示）と `deleted`（削除済み）がある
- 【内】回答の状態：`visible`（公開）／`hidden`（非表示）／`deleted`（削除）
- 【外】募集URL（`/o/{slug}`）へのアクセス時、状態に応じて表示するViewを切り替える
  - `open` → U-04
  - `awaiting_selection` → U-11
  - `decided` → U-10
  - `no_result` → U-12
  - `hidden`／`deleted` → U-13

### 0-5. シェア・計測

- 【外】XのWeb Intent URL組み立て：投稿文、URL、ハッシュタグ。文面テンプレートは設定値
- 【外】シェアボタン・CTAボタンに付ける計測用のdata属性
- 【内】イベント計測API：イベント名と属性を受け取り、生ログに保存（S-06）
- 【外】GA4への同名イベント送信
- 【外】派生元大喜利IDの引き継ぎ：「自分も大喜利を開催する」のリンクに派生元を付けてU-01へ渡す

### 0-6. キャッシュ・配信

- 【内】ページキャッシュの生成と破棄：結果確定、非表示・再公開、管理者の再生成操作をきっかけにする
- 【内】残り時間・回答数を返す軽量API（回答画面・回答一覧で使用）
- 【外】静的資産（CSS・JS・画像）をバージョン付きURLで出力

### 0-7. 広告

- 【外】広告枠の表示（画像、リンク、PR表記）
- 【内】掲載期間内の広告を枠ごとに取得し、複数あればローテーション表示
- 【内】表示回数の記録、クリックは計測用URLを経由してリダイレクト

### 0-8. 通知・運用

- 【内】管理者へのメール通知：通報、お問い合わせ、NGワード「要確認」の検知。急増時はまとめて通知
- 【内】運用設定値の読み込み（A-10）。毎リクエストでDBを引かないようキャッシュする
- 【内】アプリケーションログ（エラー、管理操作の履歴）

## 1. URLと画面の対応

URLは外側で先に確定させる。管理画面のパスは推測困難な値を `.env` で指定する（下表の `{admin}`）。

| メソッド | URL | 内容 |
|---|---|---|
| GET | `/` | U-01 トップ・開催（`?from={slug}` で派生元を受け取る） |
| POST | `/oogiri` | 大喜利の作成（U-02で同意したあと） |
| GET | `/o/{slug}/created` | U-03 開催完了（開催者トークンを持つブラウザのみ） |
| GET | `/o/{slug}` | 募集URL。状態によってU-04／U-10／U-11／U-12／U-13を表示 |
| POST | `/o/{slug}/answers` | 回答の登録（U-05で同意したあと） |
| GET | `/o/{slug}/done` | U-06 回答完了 |
| GET | `/o/{slug}/answers` | U-07 回答一覧（回答済みのブラウザのみ） |
| GET | `/o/{slug}/a/{answerId}` | 回答シェア用URL（回答シェアOGPの表示先。仕様に画面定義なし→「6. 未確定事項」を参照） |
| GET | `/host/{slug}` | U-08 開催者専用画面 |
| POST | `/host/{slug}/recover` | 合言葉による本人確認 |
| POST | `/host/{slug}/favorites/{answerId}` | お気に入りの切り替え |
| POST | `/host/{slug}/result` | 結果の確定（U-09で同意したあと） |
| POST | `/host/{slug}/delete` | 大喜利の削除 |
| GET | `/about` `/terms` `/privacy` `/guidelines` | U-14〜U-17 |
| GET / POST | `/contact` | U-18 お問い合わせ |
| GET | `/contact/done` | お問い合わせ送信完了 |
| GET | `/api/v1/o/{slug}/status` | 残り時間・回答数・状態（JSON） |
| POST | `/api/v1/events` | 計測イベント |
| POST | `/api/v1/reports` | 通報 |
| GET | `/ad/{id}/click` | 広告クリック計測とリダイレクト |
| GET / POST | `/{admin}/login` | A-01 ログイン（未ログインで開ける。IP 制限だけ） |
| POST | `/{admin}/logout` | A-01 ログアウト |
| GET / POST | `/{admin}/accounts` | A-01 管理者アカウントの一覧・追加（未確定事項10 → ADR 0007） |
| POST | `/{admin}/accounts/{id}` `/{admin}/accounts/{id}/password` `/{admin}/accounts/{id}/delete` | 名前・権限の変更、パスワード再設定、削除（上位管理者） |
| POST | `/{admin}/accounts/me/password` | 自分のパスワード変更 |
| POST | `/{admin}/ogp/regenerate-all` | A-08 公開中の OGP 画像をまとめて作り直す（予約） |
| GET / POST | `/{admin}/...` | 管理画面 A-02〜A-10 |

## 2. ユーザー向け画面

### U-01 トップ・大喜利開催（A）

- 【外】キャッチコピー、説明、「あそびかた」3ステップの表示
- 【外】お題入力欄と文字数カウンター（上限は設定値、初期値100文字）
- 【外】テンプレートの選択で入力欄へ反映、「ランダム」ボタン
- 【外】合言葉入力欄と説明文
- 【外】「24時間大喜利を開催する」ボタンで、U-02モーダルを表示
- 【外】派生元IDを hidden 項目で保持
- 【外】入力エラーの表示（入力欄の下に表示。入力内容は保持する）
- 【外】広告枠（上部・下部）
- 【内】テンプレート一覧の取得（固定配列か設定値かは未確定）
- 【内】作成処理：入力チェック、NGワード判定、レート制限、CAPTCHA
- 【内】作成処理：スラッグと開催者トークンの発行、合言葉のハッシュ保存、開始・終了日時の記録、派生元IDの保存
- 【内】作成処理：募集用OGPの生成、「開催」イベントの記録

Viewへ渡す値：`templates[]`、`fromSlug`、`limits.odaiMax`、`errors[]`、`old.odai`、`ads.top`、`ads.bottom`

### U-02 開催確認モーダル（A）

- 【外】入力したお題、遊び方2項目、注意事項4項目、規約とガイドラインへのリンクを表示
- 【外】「同意して開催する」でフォームを送信（POST `/oogiri`）
- 【外】「戻って修正する」でモーダルを閉じる（入力内容は保持）
- 【外】二重送信の防止（押したらボタンを無効化）
- 【外】JSが動かない環境でも送信できるようにする（確認はブラウザ標準の方法で代替）

### U-03 開催完了・Xシェア（A）

- 【外】お題、募集終了日時、募集URLを表示
- 【外】「Xで回答を募集する」（Web Intent）、「URLをコピー」、「開催者ページを見る」
- 【外】Xでの表示プレビュー（投稿文、OGP画像）
- 【外】開催者トークンをlocalStorageに保存（Cookieと併用）
- 【内】開催者トークンを持たないアクセスは募集URLへリダイレクト
- 【内】「募集シェア」イベントの記録

Viewへ渡す値：`oogiri.slug`、`oogiri.odai`、`oogiri.endsAt`、`shareUrl`、`intentUrl`、`ogpUrl`、`hostUrl`

### U-04 大喜利回答（A）

- 【外】状態バッジ、回答数、お題、残り時間とバーを表示
- 【外】残り時間の1分ごとの更新（状態APIを利用）。0分になったら入力を無効化して案内を出す
- 【外】回答入力欄と文字数カウンター（上限は設定値、初期値140文字）
- 【外】「回答する」でU-05モーダルを表示
- 【外】「回答すると他の人のボケが見られます」の案内
- 【外】お題の通報ボタン（共通の通報モーダル）
- 【外】広告枠（上部・下部）
- 【内】回答受付の締切判定はサーバー側で行う（画面表示に依存しない）
- 【内】回答登録：入力チェック、NGワード判定、連続投稿の判定（閾値は設定値）
- 【内】回答登録：投稿元識別情報の保存、回答数カウンタの加算、「回答」イベントの記録
- 【内】回答済みの記録（ブラウザ保存情報とサーバー側の投稿記録の両方）
- 【内】「募集URL流入」イベントの記録（リファラ、UTM）

Viewへ渡す値：`oogiri.slug`、`oogiri.odai`、`oogiri.endsAt`、`oogiri.answerCount`、`remaining`、`progressPercent`、`limits.answerMax`、`errors[]`、`old.body`、`ads`

### U-05 回答確認モーダル（A）

- 【外】お題、自分の回答、注意事項、ガイドラインへのリンクを表示
- 【外】「同意して回答する」でフォームを送信
- 【外】「修正する」でモーダルを閉じる
- 【外】二重送信の防止

### U-06 回答完了（A）

- 【外】お題と自分の回答を表示
- 【外】「この回答をXでシェア」「大喜利だけシェア」「みんなの回答を見る」「自分も大喜利を開催する」（派生元IDを付ける）
- 【外】各ボタンの計測属性
- 【内】直前に投稿した回答をセッション（フラッシュ）から取得。ない場合は募集URLへ戻す
- 【内】「回答シェア」「新規開催クリック」イベントの記録

Viewへ渡す値：`oogiri.slug`、`oogiri.odai`、`answer.id`、`answer.body`、`answerIntentUrl`、`oogiriIntentUrl`、`answerCount`

### U-07 回答後・回答一覧（A）

- 【外】上部のお題・残り時間・回答数の要約
- 【外】回答一覧（新着順）。自分の回答は強調表示
- 【外】各回答のシェアボタンと通報ボタン
- 【外】「もっと見る」（ページング。JSが動けば追記読み込み、動かなければ次ページへのリンク）
- 【外】「いいね・投票はありません」の案内、開催CTA
- 【内】回答済みでないブラウザは募集URLへリダイレクト
- 【内】非表示・削除済みの回答を除外して取得、ページングする
- 【内】自分の回答かどうかの判定（ブラウザIDで照合）

Viewへ渡す値：`oogiri`、`remaining`、`answers[]`（`id`、`body`、`postedAt`、`isMine`、`intentUrl`）、`pager`

### U-08 開催者専用（A）

- 【外】開催中の表示：お題、開始・終了日時、残り時間、PV、回答数、回答一覧、募集URL
- 【外】開催中の操作：Xで再募集、URLコピー、大喜利削除（確認ダイアログあり）
- 【外】各回答のお気に入りボタン（非公開）
- 【外】募集終了後の表示：「ベスト回答を選んでください」、選出期限の残り時間、1〜3位の枠
- 【外】タップした順に順位が入り、再タップで解除する選択UI（1件だけでも確定可能）
- 【外】「結果を発表する」でU-09を表示。選択0件のときは押せない
- 【外】合言葉入力画面（トークンがないとき）とエラー表示
- 【内】開催者の認証：トークンの照合、合言葉の照合と試行制限
- 【内】お気に入りの保存、削除処理
- 【内】状態による出し分け（開催中／選択待ち／確定後は結果ページへ）

Viewへ渡す値：`oogiri`（`slug`、`odai`、`startsAt`、`endsAt`、`selectionDeadline`、`pv`、`answerCount`、`status`）、`answers[]`（`id`、`body`、`postedAt`、`isFavorite`）、`shareUrl`、`intentUrl`、`needsRecovery`、`errors[]`

### U-09 結果確認モーダル（A）

- 【外】お題と1〜3位を表示（未選択の順位は「なし」）
- 【外】「発表後は順位を変更できません」の警告
- 【外】「この内容で結果を発表する」で送信、「選び直す」で閉じる
- 【内】結果確定：順位の保存、状態を `decided` に変更、結果用OGPの生成、結果ページキャッシュの生成、「結果確定」イベントの記録
- 【内】確定済みの大喜利への再送信は拒否する

### U-10 結果発表（A）

- 【外】結果発表の判子、お題、総回答数、募集期間
- 【外】1位（大）、2位・3位のカード
- 【外】「結果をXでシェアする」（1位の回答を含む投稿文）、「自分も大喜利を開催する」
- 【外】全回答の一覧（シェア・通報ボタン、もっと見る）
- 【外】広告枠、title／descriptionの自動設定
- 【内】ページキャッシュの対象。結果用OGPを使用する

Viewへ渡す値：`oogiri`、`ranked[]`（`rank`、`body`）、`answers[]`、`pager`、`resultIntentUrl`、`meta`、`ads`

### U-11 募集終了（A）

- 【外】結果選択待ち：「主催者がベスト回答を選んでいます」を表示
- 【外】結果確定済みの場合：「結果を見る」ボタン（仕様上の表示。実際は0-4の振り分けでU-10に直接行く→「6. 未確定事項」を参照）
- 【外】お題、集まった回答数、開催CTA

### U-12 結果未選出（B）

- 【外】「選出はありませんでした」の案内、お題、総回答数、全回答一覧、開催CTA
- 【内】ページキャッシュの対象

### U-13 非表示（A）

- 【外】公開停止の案内文（検閲ロジックや通報件数は表示しない）
- 【外】一般ユーザー向け：「新しく大喜利を開催する」
- 【外】開催者向け：修正可能な違反なら「内容を修正して再募集する」
- 【内】開催者かどうか、修正可能な違反かどうかの判定

### U-14〜U-17 紹介・規約・プライバシー・ガイドライン（A）

- 【外】静的ページのView。本文は発注者から支給されたものを差し込む
- 【外】U-14のFAQは開閉式（`<details>`）、開催CTA
- 【外】目次とページ内リンク（長文ページ）
- 【内】ページキャッシュの対象

### U-18 お問い合わせ（B）

- 【外】種別の選択、メールアドレス、対象URL、本文、CAPTCHA枠、送信ボタン
- 【外】入力エラーの表示、送信完了画面
- 【内】入力チェック、スパム対策、DBへの保存、管理者へのメール通知

## 3. 管理者向け画面

共通：

- 【外】管理画面の共通レイアウト（サイドメニュー、ログイン中の管理者名、ログアウト）
- 【外】一覧画面の共通部品（検索フォーム、並び替え、ページング、状態バッジ）
- 【内】ログイン確認のFilter、任意のIP制限、権限チェック（一般管理者／上位管理者）
- 【外】ログイン画面ができるまでの仮の管理者認証Filter（開発・ステージング用。本番では常に拒否）
- 【内】操作履歴の記録（誰が、いつ、何をしたか）

### A-01 管理者ログイン（A）

実装時期：最終工程の近く。それまでの管理画面は、仮の管理者認証で動かす（`CODING_RULES.md` の「7-1. ログイン画面ができるまでの管理画面」を参照）。

- 【外】ID（またはメール）・パスワード入力、TOTPコード入力、エラー表示

## 4. 自動処理（すべて【内】）

cronはXserverから1分間隔で Spark コマンドを実行する（`php spark cron:minute`。README の cron の表）。

- S-01 24時間終了処理：`ends_at` を過ぎた `open` を `awaiting_selection` にし、選出期限を設定する
- S-02 72時間結果待ち処理：選出期限を過ぎた `awaiting_selection` を `no_result` にし、U-12のキャッシュを生成する
- S-03 投稿監視・不正対策：判定ロジックは0-3のレート制限と共通。異常を検知したら管理画面に警告を出す
- S-04 通報処理：同一環境からの連続通報は1件として数える。条件に達したら一時非表示にし、管理者へ通知する
- S-05 AI補助判定：対象の投稿をキューに積み、cronでOpenAIへ送る。結果をA-05に表示する。APIエラー時は「未判定」とする
- S-06 計測：生ログを日次で集計テーブルにまとめ、PVのカウンタにも反映する
- S-07 OGP画像生成：募集用は開催時、結果用は確定時、回答シェア用は初回アクセス時に生成する

## 5. 外側で使うダミーデータ

外側の実装では、中身の代わりに固定のダミーデータで全画面を表示できるようにする（方法は `CODING_RULES.md` の「10. 外側と中身の分担」を参照）。最低限、次の状態を切り替えて表示確認できること。

- 大喜利：`open`（回答0件、47件）、`awaiting_selection`、`decided`（1件確定、3件確定）、`no_result`、`hidden`
- 回答：通常、自分の回答、長文（上限ちょうど）、改行を含むもの
- 開催者画面：開催中、選択待ち（未選択、2件選択）、合言葉入力
- 入力エラー：お題が空、文字数超過、NGワード、レート制限
